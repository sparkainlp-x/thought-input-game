# Experiment: would a simple extra check refuse dense random patterns?

Generated by `node scripts/gate_experiment.js`. **Optional experiment, not part of the game.** The game's gate is unchanged (tau = 0.35 on cosine, at least 3 lit cells); `npm run behaviour:check` fails if this file is stale.

**SYNTHETIC toy.** Same eight glyphs and the same `project` function as `docs/behaviour.md`, 1000 probes per stored thought for fragments and flips, 5000 random probes per scatter row, sampled with mulberry32. The numbers describe this toy on these patterns only.

## The question

A probe that lights many cells overlaps every stored thought, so the cosine gate accepts it (see section 4 of `docs/behaviour.md`). Each extra check below is applied only after the game's gate has accepted, and can only turn an acceptance into a refusal:

- **precision >= p**: the share of the probe's lit cells that are also lit in the best-matching thought.
- **probe cells <= c x best**: the probe may not light more than c times as many cells as the best-matching thought.
- **margin >= m**: the best cosine must beat the second-best cosine by m (aimed at crosstalk, not density).

## Reading the trade-off

- **3 thoughts.** 50% scatter is refused 0.1% today, 99.7% with precision >= 0.6, 100.0% with precision >= 0.7, 0.3% with probe cells <= 1.5 x best and 92.0% with margin >= 0.10.
  Cost, recalled right today -> precision >= 0.6 -> precision >= 0.7 -> margin >= 0.10: 20% fragment 99.1% -> 99.1% -> 99.1% -> 50.5%; Scramble-level noise (flip p = 0.25) 99.5% -> 91.6% -> 37.9% -> 65.5%; 15% fragment 96.2% -> 96.2% -> 96.2% -> 40.1%.
- **8 thoughts.** 50% scatter is refused 0.0% today, 99.3% with precision >= 0.6, 100.0% with precision >= 0.7, 0.1% with probe cells <= 1.5 x best and 99.4% with margin >= 0.10.
  Cost, recalled right today -> precision >= 0.6 -> precision >= 0.7 -> margin >= 0.10: 20% fragment 97.5% -> 97.5% -> 97.5% -> 55.7%; Scramble-level noise (flip p = 0.25) 96.7% -> 73.3% -> 40.6% -> 62.9%; 15% fragment 93.8% -> 93.8% -> 93.8% -> 43.8%.

What this shows, on this toy:

- A precision check does refuse dense random scatter (with a threshold of 0.6 or more, over 99% of 50% scatter), and it costs nothing on pure fragments, because every lit cell of a fragment is a cell of the thought (precision is 1).
- The price is paid on noisy drawings. The Scramble button's noise level (each cell flipped with probability 0.25) is recalled less often at precision 0.6 and much less often at 0.7, and p = 0.4 is mostly lost. These are the wrong-cells probes that the gate exists to complete, so a precision threshold trades 'refuse dense junk' directly against 'forgive wrong cells'. It is a design choice about how much wrong drawing to forgive, not a free fix.
- Filling the whole pad (all 144 cells) is accepted by the game's gate as the nearest thought; every precision, cell-count and margin 0.10 variant refuses it, while margin 0.05 refuses it only with 8 thoughts stored.
- The cell-count cap is blind to where the cells are: dense scatter has about as many cells as the thought it is matched to, so the cap barely helps (it only catches probes much bigger than the thought).
- A margin check (best cosine beats the second-best) refuses much dense scatter too, because scatter is about equally close to every thought, but it also refuses many honest fragments of similar thoughts (a 15% fragment drops by more than half at margin 0.10). It is aimed at crosstalk, and it trades recall for it.

The game keeps tau = 0.35 and none of these checks. The limit is documented in the README.
