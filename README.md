# thought-input-game

A SYNTHETIC toy and browser game. You draw a pattern on a 12 x 12 pad, and a
small associative memory either projects the whole stored pattern back from your
fragment, completes the wrong one (crosstalk), or refuses because nothing matches
well enough. Recalled patterns are shown as a hologram-style picture and played
as a short melody.

Live page: https://sparkainlp-x.github.io/thought-input-game/

## What this is not

No mind-reading, no brain-computer interface, no medical device, and no optical
hologram. A "thought" is a pattern you deliberately draw. "Holographic" is a
metaphor for the memory model described below. All numbers are SYNTHETIC: they
describe a toy on eight hand-drawn glyphs and say nothing about people, brains or
real holographic storage.

## How to play

1. A thought appears for a few seconds. Memorize it.
2. Draw it, or just its most recognizable fragment, on the thought pad. Tap or
   drag with a pointer, or move to a cell with Tab and press Space or Enter.
3. Press **Project my thought**. The membrane compares your drawing with every
   stored thought. If the best match reaches the gate threshold (tau = 0.35) it
   projects that thought back; if it is the right one you score. If not, you get
   crosstalk or a refusal and can try again.
4. **Peek** (-15 points) shows the thought again; **Fragment assist** (-10 points)
   loads a random half of it. **Hear my drawing** plays your pattern.
5. Each win teaches the membrane a new thought (Moon, Eye, Arrow, Spiral, Orbit),
   so later rounds have more crosstalk.
6. **Teach it a thought of your own** stores your drawing (at least 8 cells) in the
   same memory; **Scramble** flips 25% of the pad; **free mode** projects without
   scoring.

## How it works

The logic is in `src/membrane.js` (no dependencies, runs in the browser and in
Node); the page and round flow are in `src/game.js` and `index.html`.

- **Memory.** A list of stored 12 x 12 patterns. They are not trained into a weight
  matrix; "superposition" happens at recall.
- **Recall.** The probe is compared with each stored pattern by cosine overlap.
  The recalled field is the sum of the stored patterns, each weighted by its match
  squared. Cells above 0.38 of the strongest cell form the recalled pattern.
- **Gate.** The best match is accepted only if its cosine is at least 0.35 and the
  probe has at least 3 lit cells. Otherwise the gate refuses.
- **Sonification.** Each lit cell of a pattern is a note: its column sets the pitch
  (12 steps from 262 Hz to 1175 Hz) and its row sets the start time (120 ms per
  row; 110 ms for a recalled pattern).
- **Randomness.** Round targets, Fragment assist and Scramble use a small seeded
  generator (seed 1234567), so the sequence of targets is the same every time.

## Measured behaviour

`docs/behaviour.md` is generated by `npm run behaviour` and checked in CI. A few
headline numbers (1000 seeded random probes per stored thought, sampled with
mulberry32; SYNTHETIC):

- With 3 stored thoughts, a fragment of 20% of a thought's cells is recalled
  correctly 99.1% of the time, and fragments of 30% or more 100%. A fragment of 10%
  (about 7 cells) is refused 98.7% of the time.
- With all 8 thoughts stored, a fragment of 20% is recalled correctly 97.5% of the
  time, 50% 99.8%, and 15% 93.8%; the rest are crosstalk (a similar thought) or refusals.
- Whole patterns with 25% of cells flipped (the Scramble button) are recalled
  99.5% of the time with 3 thoughts and 96.7% with 8. At 50% flips the memory is at
  chance level and crosstalk dominates (87.2% crosstalk with 8 thoughts).
- The gate refuses sparse random scatter (5% density: 99.8% with 3 thoughts,
  99.2% with 8) but not dense scatter (see "Honest limits").
- Similar thoughts interfere: Tree and Arrow share cosine 0.86 (Jaccard 0.74).

## Honest limits

- It is a toy memory on eight glyphs. Capacity, noise tolerance and crosstalk would
  differ for other pattern sets. Fragments in the tables contain only correct cells.
- The gate only measures cosine overlap, so dense patterns pass it. Random scatter
  is refused 99.8% (3 thoughts) and 99.2% (8) at 5% density, but only 19.8% and 4.2%
  at 30% density, 2.5% and 0.1% at 40%, and 0.1% and 0.0% at 50%. Filling the whole
  pad (144 cells) is accepted as the nearest thought. A probe that lights many cells
  overlaps every stored thought. `docs/gate-experiment.md` is an OPTIONAL experiment
  (not part of the game; tau stays 0.35): a precision check (share of the probe's
  cells that lie in the best match) of 0.6 or more refuses over 99% of 50% scatter and
  costs nothing on pure fragments, but it also refuses noisy drawings (recall at the
  Scramble noise level falls from 99.5% to 91.6% with 3 thoughts and from 96.7% to
  73.3% with 8 at precision 0.6). That is a design choice about how much wrong
  drawing to forgive, so it was not adopted.
- The recalled pattern is the stored thought plus or minus cells that overlapping
  thoughts contribute; it is rarely cell-for-cell identical (mean overlap with the
  stored thought is 0.76 to 0.91 in the fragment tables).
- The game's own random generator is deterministic but weak (a cycle of 10,466 draws
  after a 2,423-draw lead-in; see `docs/behaviour.md`, section 6). It is fine for
  choosing a round target; it is not a source of statistical randomness. The tests and
  the measurement scripts use a separate generator (mulberry32), and the tables
  agree with the legacy generator to within 0.4 points (section 6b).
- The memorize phase (3.5 seconds, 5 seconds for a newly learned thought), the point
  values and the glyphs are design choices, not measurements.

## Changes from the original single-file game

The page started as one HTML file. The behaviour was kept; tests compare the
extracted logic with the original code (kept in `test/fixtures/`) for the random
sequence, the glyphs and 3000 random projections. Differences, all covered by tests:

- Fixed: the Project button was re-enabled by a free-mode projection after a round
  was already won, so a won round could be scored again (and unlock another thought)
  by pressing Project after Project - free mode. It stays disabled now.
- Fixed: a free-mode projection in an open round left Peek disabled and made
  Fragment assist do nothing until another game projection. Both work again.
- Fixed: the pad cells are buttons but only reacted to pointers, so a keyboard user
  could not light a cell. Space and Enter toggle the focused cell now.
- Accessibility: the verdict is an `aria-live` region, the game status is a labelled
  group, the hologram canvas has `role="img"`.
- Privacy: the page no longer requests Google Fonts; it uses system fonts.
- Wording: the "Honest limits" footer now states that the memory is a list of patterns
  combined into a weighted field, not a trained matrix.
- Fixed: when you store a thought that is close (Jaccard above 0.7) to two stored
  thoughts, the warning now names the closest one; the original named the last one.
  Only the name in the message changes. With the eight built-in thoughts only Tree
  and Arrow (0.74) are that close, so it matters only when a Tree-like drawing is
  stored while Arrow is stored too.
- Added, not used by the game: `createMulberry32` and `createRng(seed, "mulberry32")`,
  a well-defined generator for tests and measurements. The game still uses the
  original generator (`createRng(seed)` is unchanged), so the sequence of round
  targets is the same as before. That generator is not the integer LCG it appears to
  be (see `docs/behaviour.md`, section 6); replacing it would change the target
  sequence, so it was left as is and pinned by a test.

## Accessibility

- Every pad cell is a button with an `aria-label` ("Cell row 3 column 5") and
  `aria-pressed`; keyboard: Tab to a cell, Space or Enter to toggle. Drag-painting
  needs a pointer; the keyboard path lights one cell at a time.
- Status messages use `role="status"`; the verdict uses `aria-live="polite"`.
- Colour scheme follows the system (light or dark), and the hologram animation is
  reduced when the system asks for reduced motion.
- Sound is optional (the Sound button); every sound has a visible equivalent.
- Not checked: screen-reader use beyond the attributes above, and colour contrast
  against a formal standard.

## Privacy

The page runs entirely in your browser. Nothing you draw or name is stored or sent
anywhere: there is no network request after the page loads, no cookies and no local
storage. Fonts are system fonts (the original loaded IBM Plex from Google Fonts;
that request was removed). Hosting on GitHub Pages means GitHub sees an ordinary page
request.

## Development

```
npm test               # unit tests (node:test, no dependencies)
npm run check:text     # wording and privacy rules
npm run behaviour      # regenerate docs/behaviour.md
npm run behaviour:check   # also checks docs/gate-experiment.md
npm run gate:experiment   # regenerate docs/gate-experiment.md (optional experiment)
npm install            # only needed for the browser tests
npm run e2e            # headless browser tests (Playwright; set CHROME_PATH to use an installed Chrome)
```

CI runs the unit tests on Node 20 and 22, the wording check, the behaviour check and
the browser tests; the Pages workflow publishes `index.html` and `src/`.
